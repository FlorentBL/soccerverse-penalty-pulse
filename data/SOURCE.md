The [official datapack](https://soccerverse.com/developers/datapack-and-assets) supplies IDs and display names, not playable statistics, positions or ownership. `player-ids.bin` and `rules/pulse/player_bits.inc` are the same membership bitset. `public/players/*.json` are display-name shards. The 1,985 records with missing first and last names display as `Soccerverse player #ID`. Regenerate names with `python3 scripts/generate-soccerverse-snapshot.py /path/to/default.json`; the script rejects any source with a different SHA-256.

## Primary positions

- Source: the [official Soccerverse MCP](https://soccerverse.com/developers/soccerverse-mcp) public `search_players` tool, field `position_main`. The relevant codes returned by the API are `FC` and `GK`; for example, Harry Kane is `FC`, Hugo Lloris is `GK`, and Bukayo Saka is `FR`.
- Fetched: 2026-09-26, approximately 18:51–19:00 UTC, in 1,791 batches of at most 100 IDs. This is an API snapshot across calls, not a single chain-height snapshot. All 179,100 pinned IDs returned a nonempty primary position; `/tmp/pulse-soccerverse-positions` caches validated batches for a resumable fetch.
- `data/player-fc-bits.bin`: 65,447 bytes, 30,715 primary `FC` players, SHA-256 `6c11108dc5e6cc56e4f7250e271e42f8fda2d31f5ff260328ab629ccd54ec90d`.
- `data/player-gk-bits.bin`: 65,447 bytes, 19,955 primary `GK` players, SHA-256 `723ca7fcd919ce383a6d5762981413a90e693c60dab5c7e20543e0569ee72c8c`.
- Generate the C++ and browser copies with `python3 scripts/generate-position-assets.py`. This also generates the WASM roster from `src/lib/pulse/featured.json` after validating exactly three `FC` shooters and three `GK` keepers, one in each rating band. Re-fetch with `python3 scripts/fetch-soccerverse-positions.py` after deleting the cache to obtain a new live snapshot; changing it changes the WASM consensus hash. During a match, only the six fixed roster players can be selected. Custom IDs are rejected. Secondary positions do not qualify.

## Shooting ratings

- Source: [official Soccerverse MCP](https://soccerverse.com/developers/soccerverse-mcp), public `search_players` tool at `https://mcp.soccerverse.io/mcp`, which exposes the Datacentre `/players` records.
- Fetched: 2026-09-26, approximately 08:09–08:12 UTC. This is an API snapshot across 1,791 batches, **not** a single chain-height snapshot. Ratings can change in Soccerverse after collection; Arcade matches always use these pinned bytes.
- Selected IDs: exactly the 179,100 IDs in the pinned datapack, queried in batches of 100. All 179,100 returned an integer `rating_shooting` between 0 and 100. No datapack player was missing a rating at collection time.
- `data/player-shooting.bin`: 523,572 bytes, indexed by player ID; `255` in unused ID slots. SHA-256: `fe0eb9c810a27f17f6ad605ee29669449774bc2a55603e0cfaa6c1e1065abfd6`.
- C++ and browser copies, `rules/pulse/player_shooting.inc` and `src/lib/pulse/shooting-data.ts`, are generated with `python3 scripts/generate-shooting-assets.py` from that binary. Regenerate the snapshot with `python3 scripts/fetch-soccerverse-shooting.py`; the script checks IDs, pagination and values and caches batches under `/tmp/pulse-soccerverse-ratings` to resume a long fetch. Delete that cache first to obtain new live ratings; changing the snapshot changes the WASM consensus hash.

Arcade maps the official rating to reliable goal zones: 55–59 → 3, 60–64 → 4, 65–69 → 5, 70–79 → 6, 80–89 → 7, 90–100 → 8. Ratings below 55 are ineligible for selection. At least one of the nine zones is always unreliable. These thresholds and the exact ID-based arrangement of the zones are **Arcade rules**, not Soccerverse statistics. Ownership is neither checked nor required. No live Soccerverse request is made during a match.

## Goalkeeper ratings and role balance

- Source: the same [official Soccerverse MCP](https://soccerverse.com/developers/soccerverse-mcp) public `search_players` endpoint, field `rating_gk`.
- Fetched: 2026-09-26, approximately 15:35–15:38 UTC, in 1,791 batches. This is an API snapshot across calls, not a single chain-height snapshot. The cache in `/tmp/pulse-soccerverse-goalkeeping` supports resuming; deleting it before rerunning obtains fresh live values and changes consensus bytes.
- All 179,100 pinned player IDs returned integer `rating_gk` values between 0 and 100. No datapack player was missing.
- `data/player-goalkeeping.bin`: 523,572 bytes, indexed by player ID; 255 in unused slots. SHA-256: `e615569b6699fdc1dbdb3bfd0bf0b0ec1f3b514ee006e3e71fb2a9e849dc60f2`.
- The C++ and browser tables, `rules/pulse/player_goalkeeping.inc` and `src/lib/pulse/goalkeeping-data.ts`, are generated by `python3 scripts/generate-goalkeeping-assets.py`. Fetch with `python3 scripts/fetch-soccerverse-goalkeeping.py`.
- Arcade requires a separate `FC` shooter and `GK` goalkeeper for each pair of penalties. In regulation, each seat uses each rating tier (90+, 75–89, 55–74) once in each role. Keeper ratings of 55–74 cover one zone; 75–89 cover two adjacent zones; 90+ cover any two distinct zones. Against a shooter with only three reliable zones, all keepers cover one. These are **Arcade rules**, not Soccerverse attributes. See `python3 scripts/measure-balance.py` for exact mixed-strategy one-penalty values from both pinned rating tables (requires SciPy).
